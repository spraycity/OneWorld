# Contributing to ONEWORLD

Thank you for helping make language access more equal.

## Ways to contribute
- code, testing, documentation, design, accessibility;
- language review and terminology work;
- device compatibility testing;
- privacy and security review;
- low-resource language research and community partnerships.

## Before opening a pull request
1. Search existing issues and discussions.
2. For substantial changes, open an issue or discussion first.
3. Keep changes focused and document trade-offs.
4. Add tests for behavior changes.
5. Do not commit private audio, transcripts, personal data, API keys, or model files unless their redistribution rights are documented.
6. Identify the license of every added model, dataset, voice, and dependency.

## Pull request checklist
- [ ] The purpose and user impact are clear.
- [ ] Privacy implications are described.
- [ ] Accessibility has been considered.
- [ ] Tests or manual test steps are included.
- [ ] Third-party license and attribution requirements are recorded.
- [ ] Documentation is updated.

## Language contributions
Language contributors should identify dialect, region, register, and review status where relevant. Machine-generated translations must not be presented as community-verified. Contributors must not upload recordings or personal data without informed permission from every identifiable speaker.

## Decision making
Small, reversible changes may be reviewed by maintainers. Changes affecting privacy, governance, licensing, data collection, or the project's mission require public discussion and a recorded decision under `GOVERNANCE.md`.
